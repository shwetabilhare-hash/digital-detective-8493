## 3. Commands / tools used

| Git operation | What it does in my own words |
|---|---|
| git init | Turns a folder into a Git repository |
| git status | Shows which files are changed, staged or untracked |
| git add | Stages selected changes so they are ready to be saved |
| git commit | Saves the staged changes as a snapshot with a message |
| git log --oneline | Shows the history of commits in a short list |
| git branch | Lists branches, or creates one |
| git switch | Moves to another branch |
| git push | Sends my commits to GitHub |
| git pull | Brings the latest changes from GitHub to my computer |

## 4. My understanding

- **Staging vs committing:** Staging (git add) chooses which changes go into the next snapshot. Committing (git commit) actually saves that snapshot in the history.
- **Branch:** A branch is a separate line of work. I can make changes on it without touching the main branch.
- **Pull Request:** A Pull Request asks to bring the changes from one branch into another, such as update-about into main. People can review the changes before they are merged.
- **Why useful:** When many people work on the same project, branches stop them from breaking each other's work, and Pull Requests let others review changes first.
